About this trail

The Jewish India Digital Heritage Trail is a working catalogue of the built and spatial heritage of India's Jewish communities — the Bene Israel, the Baghdadi (including the Sassoon family network), the Cochini and other Jews of Kerala, communities of the broader Indian Jewish diaspora, and emerging communities such as the Bene Menashe.

Data sources

The map currently draws on a GeoJSON dataset of Jewish heritage sites in Bombay and the Deccan, a spreadsheet of synagogues across India, Pakistan, and Burma, the field survey of approximately 42 Jewish cemeteries by Isaac Solomon, and an image collection covering individual sites and the Sassoon Mills label and agreement archive. Where founding dates, communities, or coordinates are inferred rather than recorded, the entry is marked as such and should be treated as preliminary.

The data structure

Every site on the trail — synagogue, cemetery, mill, school, garden — is one entry in a single dataset. Each entry has the same set of fields, listed below. Empty fields are fine; the site only renders what's there.

Editing data from a Google Sheet

You don't need to touch JSON. The recommended workflow is to keep all entries in a Google Sheet using the columns above, then sync that sheet to the site whenever you make changes.

One-time setup

  1. Create a new Google Sheet. Use the column headers from the table above as the first row, exactly as written (lowercase, with underscores).
  2. To avoid typing them, download the starter template here: sheet-template.csv — open it, then in Google Sheets choose File → Import → Upload.
  3. In Google Sheets, go to File → Share → Publish to web. Pick the sheet (or "Entire Document"), choose Comma-separated values (.csv), and click Publish. Copy the URL it gives you — it looks like https://docs.google.com/spreadsheets/d/…/pub?output=csv.

Each time you want to update the site

  1. Edit your sheet — add rows, fix typos, fill in coordinates, write descriptions.
  2. From inside the jewish-india-trail/ folder, run: 
    python sync-from-sheet.py "<your published-csv URL>"
    The script overwrites data/features.json and rebuilds data/features.js (the inline copy used so the site works without a server). If you set SHEET_URL at the top of the script once, you can just run python sync-from-sheet.py with no arguments.
  3. Reload the site in your browser. Your sheet's data is now live.

Image lists are not stored in the sheet — they're discovered by scanning the matching image_folder on disk. If you've added new photos, run python rebuild.py after the sync to refresh the image lists.

What happens to existing fields when you sync?

The sync overwrites every field that the sheet defines. It preserves per-site image lists discovered by rebuild.py — so you can keep editing the sheet without losing the photo references. If you remove a row from the sheet, that site disappears from the next sync.

How to add images

For sites already in the Bombay/Deccan dataset, drop images into the matching folder under Images/ (e.g. Images/Magen David Synagogue/) and run python rebuild.py. For the Sassoon Mills collection, images live under Images/jewish-india-trail/images/mills/. Where you have IIIF manifests, the data model includes an iiif_manifest field — a future iteration of this site can wire those directly into a Mirador or OpenSeadragon viewer.

Sustainability

This site is built as plain HTML, CSS, and JavaScript — no build step, no database. It can be hosted free on GitHub Pages, Netlify, or Cloudflare Pages, or simply opened from a folder. Map tiles come from CARTO's free Positron basemap; map rendering uses the open-source Leaflet library. Because all data is in a single JSON file (or a Google Sheet that produces one), the site is straightforward to migrate later to a static site generator such as Astro if you want per-feature markdown pages.
